# Data location and control

## Input

List inventory, telemetry, alarms, user identities, logs, support records and backups. For each category, note sensitivity, purpose, source and owner. Do not upload the completed list publicly.

## Review table

| Field to record | Evidence to request |
| --- | --- |
| Storage and backup locations | Actual configuration and provider terms |
| Administrative access | Named roles and dated access review |
| External transfers | Destination and field-level flow inventory |
| Retention and deletion | Defined periods and demonstrated deletion path |
| Portability and exit | Export format and tested readable export |
| Encryption and key ownership | Configuration and recovery responsibility |

## Validation

Use an invented record to exercise export and deletion in an agreed test environment. Verify copies, logs and backups against the stated policy. Mark a backup deletion limitation explicitly rather than assuming immediate removal.

## Output and limit

Retain a data-flow register and unresolved questions with owners. Local hosting does not settle administrative access, international transfers, legal duties or practical control. The public lab has only invented data; it does not establish how a private deployment handles personal or operational information.
