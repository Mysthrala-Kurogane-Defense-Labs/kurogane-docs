# Glossary

| Term | Meaning in these repositories |
| --- | --- |
| OT | Systems that interact with physical processes; constraints on safety, availability and vendor support matter |
| IT | Information systems and services; their identities, networks and backups can also be dependencies of OT |
| Asset register | Dated list of assets, owners, dependencies and evidence; completeness must be verified |
| Satellite | Conceptual source-side integration component; no deployed private topology is proven here |
| Event contract | Required fields and accepted data values; not authentication or delivery assurance |
| Dry run | Local preview that performs no HTTP request |
| Telemetry gap | Missing observations over an interval; cause is unproven without additional evidence |
| Digital twin | A stronger modeling claim than the public synthetic asset inventory demonstrates; see its [scope questions](digital-twin-overview.md) |
| Data sovereignty | A question of location, access and practical/legal control; local hosting alone is insufficient |
| SBOM | Software component inventory tied to an artifact and version; not a certificate of freedom from vulnerabilities |
| NIS2 | EU directive whose scope and national implementation require an applicability review |
| METI SCS | Japanese supply-chain IT security evaluation scheme; do not label it generic OT certification |
| Evidence | Dated, scoped record that supports a specific claim; unknowns remain explicit |
